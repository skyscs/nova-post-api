# Анализ проблемы автообновления базы данных

## 🚨 Проблема

После суток работы автоматического обновления база данных оказалась полностью пустой.

## 🔍 Найденные причины

### 1. Критическая ошибка в `bulkCreateDivisions()`

**Местоположение**: `src/services/divisionService.ts:21`

**Проблема**: Метод сначала выполнял `TRUNCATE TABLE divisions CASCADE`, полностью очищая базу данных, а только потом пытался загрузить новые данные. Если процесс загрузки прерывался (ошибка сети, нехватка памяти, etc.), база оставалась пустой.

```typescript
// СТАРЫЙ ОПАСНЫЙ КОД:
await client.query('TRUNCATE TABLE divisions CASCADE'); // ← очищает ВСЕ данные сразу
// ... затем пытается загрузить новые данные
```

### 2. Неправильный парсер данных в cron job

**Местоположение**: `src/services/updateService.ts:24-60`

**Проблема**: Метод `checkForUpdates()` использовал устаревший парсер `parseDivisionData()`, который не понимал структуру NovaPost API. В результате даже если данные скачивались, они парсились неправильно.

### 3. Отсутствие отката (rollback)

Если процесс обновления падал, не было механизма восстановления предыдущих данных.

## ✅ Исправления

### 1. Безопасный метод обновления базы

**Новый алгоритм**:
1. Создается временная таблица
2. Данные загружаются во временную таблицу  
3. Проверяется целостность данных
4. Только после успешной проверки очищается основная таблица
5. Данные копируются из временной в основную таблицу

```typescript
// НОВЫЙ БЕЗОПАСНЫЙ КОД:
// 1. Создаем временную таблицу
await client.query(`CREATE TEMP TABLE temp_divisions (LIKE divisions INCLUDING ALL)`);

// 2. Загружаем данные во временную таблицу
// ... batch insert в temp_divisions ...

// 3. Проверяем данные
const tempCount = await client.query('SELECT COUNT(*) FROM temp_divisions');
if (parseInt(tempCount.rows[0].count) !== divisions.length) {
  throw new Error(`Data verification failed`);
}

// 4. Только теперь очищаем основную таблицу и заменяем данные
await client.query('TRUNCATE TABLE divisions CASCADE');
await client.query(`INSERT INTO divisions SELECT * FROM temp_divisions`);
```

### 2. Исправлен парсер данных

Cron job теперь использует проверенный метод `updateFromApi()` вместо устаревшего `parseDivisionData()`.

```typescript
// Было:
await this.updateDatabase(latestVersion.url);  // использовал старый парсер

// Стало:
const result = await this.updateFromApi();     // использует правильный парсер
```

### 3. Удален небезопасный код

Удалены методы:
- `updateDatabase()` - небезопасное обновление
- `parseDivisionData()` - неправильный парсер  
- `mapApiDataToDivision()` - устаревшее мапирование

## 🕐 Настройки cron job

**Текущие настройки**: `0 2 * * *` (каждый день в 2:00 утра)

**Переменная окружения**: `UPDATE_CRON=0 2 * * *`

**Как изменить время**: 
```bash
# Для обновления в 3:00 утра
UPDATE_CRON=0 3 * * *

# Для обновления каждые 6 часов
UPDATE_CRON=0 */6 * * *
```

## 🔄 Процесс автообновления

1. **Cron job запускается** (по умолчанию в 2:00)
2. **Проверяется версия** на NovaPost API
3. **Сравнивается** с последним успешным обновлением в БД
4. **Если есть новая версия**:
   - Скачивается файл базы (402MB)
   - Парсится структура NovaPost
   - Извлекаются регионы и города
   - **Безопасно обновляется** база через временные таблицы
5. **Логируется** результат в `update_logs`

## 🛡️ Меры безопасности

### 1. Валидация данных
- Проверка количества загруженных записей
- Валидация структуры данных
- Проверка обязательных полей

### 2. Транзакции
- Все операции выполняются в транзакциях
- При ошибке автоматический rollback

### 3. Логирование
- Все операции записываются в `update_logs`
- Сохраняются детали ошибок
- Метрики производительности

### 4. Резервные копии
Рекомендуется настроить автоматические бэкапы PostgreSQL:

```bash
# Ежедневный бэкап в 1:00 (за час до обновления)
0 1 * * * pg_dump nova_post_db > /backups/nova_post_$(date +\%Y\%m\%d).sql
```

## 📊 Мониторинг

```bash

```

```bash

GET /api/v1/system/status         # статистика БД
GET /api/v1/system/update-status  # статус последнего обновления
GET /api/v1/system/updates/history # история обновлений
```

## ⚠️ Что делать если база снова очистилась

1. **Остановить сервер** (чтобы предотвратить дальнейшие попытки обновления)
2. **Восстановить из бэкапа** (если есть)
3. **Или загрузить данные заново**:
   ```bash
   # SSH на сервер
   cd /path/to/nova-post-api
   bun run cli:update  # или bun src/cli/update.ts force-update
   ```
4. **Проверить логи** для выяснения причины
5. **Запустить сервер**
